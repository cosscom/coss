`coss` is the official TypeScript SDK. It has zero dependencies, is fully typed and runs on
Node.js 22+, Bun, Deno and Cloudflare Workers.

```package-install
coss
```

## The client

One client covers every product. Create it once and reuse it. Each endpoint's page in the
[API reference](/docs/api-reference) shows its SDK call in the **TypeScript** tab; these pages cover
how the client itself behaves.

```ts twoslash
import { Coss } from "coss";

const coss = new Coss({ apiKey: process.env.COSS_API_KEY });
//    ^?
```

Hover any identifier in these examples to see its type.

## Options

```ts twoslash
import { Coss } from "coss";
// ---cut---
const coss = new Coss({
  apiKey: "coss_test_...",
  baseUrl: "https://api.coss.com",
  timeout: 30_000,
  maxRetries: 2,
  dangerouslyAllowBrowser: false,
});
```

| Option                    | Default                                         | Description                                                |
| ------------------------- | ----------------------------------------------- | ---------------------------------------------------------- |
| `apiKey`                  | `COSS_API_KEY`                                  | A `coss_live_…` or `coss_test_…` key                       |
| `baseUrl`                 | `COSS_BASE_URL`, then `https://api.coss.com`    | The API origin                                             |
| `timeout`                 | `30000`                                         | Per-attempt timeout in milliseconds                        |
| `maxRetries`              | `2`                                             | Retries for network errors, timeouts, 409, 429 and 5xx     |
| `fetch`                   | global `fetch`                                  | A custom `fetch` implementation                            |
| `dangerouslyAllowBrowser` | `false`                                         | Allow running where `document` exists (exposes your key)   |
| `tracing`                 | `true`                                          | An OpenTelemetry span per call, when `@opentelemetry/api` is installed ([Tracing](/docs/api-reference/tracing)) |

The constructor throws only for programmer errors: a missing API key, or running in a browser
without `dangerouslyAllowBrowser`.

## Results, not exceptions

Every method returns `{ data, error }`. API and network failures come back as `error`; they are
never thrown. Checking `error` narrows `data`:

```ts twoslash
import { Coss } from "coss";
const coss = new Coss();
// ---cut---
const result = await coss.email.get("email_01k7c8m4q2f3e9v6t5r1n0p8yz");

if (result.error) {
  console.error(result.error.message);
} else {
  console.log(result.data.subject);
  //                 ^?
}
```

## Per-request options

Methods take an optional last argument. Every method accepts an `AbortSignal`; `send` also takes an
idempotency key.

```ts twoslash
import { Coss } from "coss";
const coss = new Coss();
const params = { from: "a@acme.com", to: "b@example.com", subject: "Hi", text: "Hi" };
// ---cut---
const controller = new AbortController();

await coss.email.send(params, { idempotencyKey: "welcome-user-123", signal: controller.signal });
await coss.email.get("email_01k7c8m4q2f3e9v6t5r1n0p8yz", { signal: controller.signal });
```

## Any endpoint

`coss.request()` calls an endpoint by its path, for one the SDK has no method for yet. It takes
the client's key, version, timeout and retries, and returns the response's JSON as `{ data, error }`,
unchecked (pass a type to describe it):

```ts twoslash
import { Coss } from "coss";
const coss = new Coss();
// ---cut---
const { data, error } = await coss.request<{ data: { id: string }[] }>("GET", "/v1/domains", {
  query: { limit: 5 },
});

await coss.request("POST", "/v1/domains/dom_01k7c8m4q2f3e9v6t5r1n0p8yz/verify");
```

GET and DELETE are retried like every other call; POST, PUT and PATCH only with `retry: true`,
since not every endpoint deduplicates them (saving a template's draft counts every attempt as a
revision). `responseType: "text"` or
`"bytes"` reads a body that isn't JSON (a CSV export, a received email's raw message).

## Diagnose a delivery

`coss/diagnose` explains what happened to an email: a verdict, what each recipient's status means
(a bounce with the receiving server's reason, a suppression with its entry, a delay, a failure and
its cause), account problems that affect it and what to do next. `diagnose` reads the email, its
events and the account context it needs; `diagnoseEmail` is the pure part, for data you already
have. The CLI's `coss emails diagnose` and the MCP server's `diagnose_email` use it too.

```ts twoslash
import { Coss } from "coss";
const coss = new Coss();
// ---cut---
import { diagnose } from "coss/diagnose";

const { data, error } = await diagnose(coss, "email_01k7c8m4q2f3e9v6t5r1n0p8yz");
if (data) {
  console.log(data.verdict, data.summary);
  //               ^?
  for (const recipient of data.recipients) console.log(recipient.address, recipient.explanation);
}
```

## Runtimes

The package is ESM-only and uses nothing but `fetch`, `AbortSignal` and `crypto.randomUUID`.
Environment fallbacks read `process.env` where it exists; on Workers or Deno without env access,
pass `apiKey` (and `baseUrl`) explicitly.
