<Section title="One prompt" lede="Paste this into Claude Code, Cursor, Codex or any coding agent. It reads the docs, gets a sandbox key and tests what it builds.">

```text
Add coss.com to this project: read https://coss.com/llms.txt, get a development key with `npx coss-cli init --agents`, and build and test with it.
```

From there the agent asks you to approve a development key in your browser, installs the SDK and runs its code against that key. Development keys deliver nothing: emails and SMS get simulated outcomes, events and webhooks. [Coding agents](/docs/agents) has the details.

</Section>

<Section title="What the agent gets" lede="Every surface an agent touches is written for it: the docs, the key, the tools and the SDK's results.">

<Features>

<Feature title="Docs as Markdown">
[/llms.txt](/llms.txt) starts with a brief (getting a key, how the SDK reports errors, testing webhooks) and lists every page. Every docs page is Markdown at its URL plus `.md`, and [/llms-full.txt](/llms-full.txt) has every guide in one file.
</Feature>

<Feature title="A key without copy and paste">
`npx coss-cli init` opens the dashboard, you approve a key for that project (sandbox environments only), and it writes `COSS_API_KEY` to `.env.local` or `.env` and installs `coss`. Over SSH it prints a link and waits for a code. [CLI](/docs/cli#set-a-project-up).
</Feature>

<Feature title="Notes for later sessions">
`init` adds a short coss.com section to the project's `AGENTS.md` (or `CLAUDE.md`), so the next session knows where the docs are and how to test. It detects Nodemailer, Better Auth, Auth.js, Laravel, Rails and Django and prints that drop-in.
</Feature>

<Feature title="An MCP server">
`coss-mcp` searches and reads the docs, finds emails and SMS, explains why one wasn't delivered, reads logs, and manages domains, suppressions, webhooks, templates, inboxes and Risk. [MCP server](/docs/mcp).
</Feature>

<Feature title="A plugin and an Agent Skill">
The Claude Code plugin adds a skill that loads when a task involves coss.com, and the MCP server. The same skill installs into Cursor, Codex, GitHub Copilot and Windsurf with `npx skills add cosscom/coss`.
</Feature>

<Feature title="Results agents can read">
Every SDK method returns `{ data, error }` and never throws for API or network failures. Errors carry a `type`, a `code`, the field's `issues` and often a `hint` with a docs URL, so the agent fixes its own request.
</Feature>

</Features>

</Section>

<Section title="The MCP server" lede="coss-mcp is a Model Context Protocol server that runs locally through npx and calls coss.com with your API key.">

```sh
claude mcp add coss -e COSS_API_KEY=coss_test_… -- npx -y coss-mcp
```

Ask it "did the welcome email to jane@example.com get delivered?" and `diagnose_email` answers with a verdict, what happened to each recipient and why, problems with the account and what to do next. `get_setup` is its first call before writing send code: the key's mode, a from address that will succeed, missing DNS records and one next step.

- **Docs**, with no key: `search_docs`, `read_docs`.
- **Email**: `diagnose_email`, `find_emails`, `get_email`, `send_email`, suppressions, domains and templates.
- **SMS**: `diagnose_sms`, `find_sms`, `send_sms`, numbers and suppressions.
- **Webhooks and logs**: `list_webhook_deliveries`, `retry_webhook_delivery`, `create_webhook_endpoint`, `search_logs`.
- **Inboxes and receiving**: `create_inbox`, `get_inbox_thread`, `reply_to_inbox_message`, `list_received_emails`.
- **Hooks, Forms and Risk**: `send_hook_message`, `list_form_submissions`, `assess_risk`.

Email content, received mail, bounce messages and webhook responses are written by other people: the server labels them untrusted and tells the agent to treat them as data, never as instructions. Without `COSS_API_KEY` it reads only a development key from the project's env file, never a `coss_live_` one.

</Section>

<Section title="Safe to retry, safe to test" lede="Agents retry and run code repeatedly. coss.com makes both harmless.">

```ts twoslash
import { Coss } from "coss";
const coss = new Coss();
declare const user: { id: string; email: string };
// ---cut---
const { data, error } = await coss.email.send(
  {
    from: "Acme <hello@acme.com>",
    to: user.email,
    subject: "Welcome to Acme",
    text: "Thanks for signing up.",
  },
  { idempotencyKey: `welcome-${user.id}` }, // a rerun sends nothing twice
);

if (error) console.error(error.code, error.hint); // what to change, not a stack trace
```

The SDK sends an `Idempotency-Key` with every `POST` and reuses it when it retries, so a retried send goes out once. `coss listen` forwards sandbox webhooks to `localhost`, and `coss trigger` sends a sample event of any type, so an agent can test its webhook handler end to end.

</Section>
